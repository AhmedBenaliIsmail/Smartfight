# SmartFight - Technical Architecture & Developer Manual

## 1. Project Overview
SmartFight is a comprehensive, enterprise-level MMA/Boxing management platform built with Symfony 7. It provides advanced tools for roster management, bout scheduling, match analytics (CompuBox style), fan engagement (Fantasy League, Voting), and financial contract management.

## 2. Core Architecture & Technologies

### Backend Framework
- **Symfony 7 (PHP 8.2+)**: The core framework providing MVC architecture.
- **Doctrine ORM**: Object-Relational Mapping for database interactions.
- **Twig**: The templating engine used for rendering views.

### Frontend Technologies
- **Tabler UI (Bootstrap 5)**: The primary admin dashboard framework providing a responsive, professional dark-mode interface.
- **Vanilla JavaScript / Fetch API**: Used for asynchronous interactions like AI Matchmaking generation and FaceID polling.
- **Face-api.js**: A local TensorFlow.js wrapper used for the FaceID biometric login system.

### APIs & External Services
- **DeepSeek API**: 
  - **Matchmaking Engine**: Analyzes the fighter roster (ELO, division, win-rate) to suggest high-excitement match proposals.
  - **CompuBox Analytics**: Generates realistic round-by-round statistics based on fighter attributes (style, recent form, weaknesses).
  - *Note: A local fallback engine is implemented to ensure the platform functions even if API credits expire.*
- **Google OAuth (KnpUOAuth2ClientBundle)**: Provides "Sign in with Google" functionality.

## 4. Core Entities & Database Logic

The platform relies on several interconnected database entities:

1. **User / Role**: Manages authentication. Users log in via Username or Email. Passwords are encrypted using modern hashing algorithms.
2. **Fighter & WeightDivision**: The core athletes. Fighters have physical attributes, records, ELO ratings, and an AI-calculated fighting style.
3. **Event**: Fight cards. Includes specialized logic to flag "Champions Events" which trigger 1.5x performance multipliers for fighters.
4. **FightResult & FightStatistic**: Stores bout outcomes. `FightStatistic` tracks round-by-round "CompuBox" data (punches thrown, landed, knockdowns, etc.).
5. **MatchProposal**: Bouts generated by the AI Engine or Admin that are put into the Fan Dashboard for community voting.
6. **Prediction**: Fan Fantasy League entities where users predict bout outcomes to earn points.
7. **FighterContract**: Financial engine calculating base pay, win bonuses, and sponsorship cuts based on the event revenue.

## 5. System Logic & Workflows

### Authentication Flow
- **Standard Login**: Validates against the `user` table. Supports FaceID integration (uses local browser webcam to match biometric hash).
- **Password Recovery**: Uses `symfony/mailer` over Port 587 (TLS) to send secure, time-sensitive reset tokens.

### Statistical & Ranking Engine
When a `FightResult` is finalized by an administrator:
1. **ELO Recalculation**: The system calculates the probability of victory based on ELO disparity and awards points accordingly.
2. **Performance Multipliers**: If the fight occurred on a "Champions Event" card, the ELO exchange and performance points are multiplied by 1.5x.
3. **Record Updates**: Updates the Winner's and Loser's W-L-D record automatically.

### AI Matchmaking & Fallback System
When the "AI Generate Proposals" button is clicked:
1. The backend builds a JSON prompt containing the entire roster's current statistics.
2. It sends this to DeepSeek to find the most competitive matchups.
3. **Fail-Safe Logic**: If the API fails (timeout, 402 Insufficient Balance), the `AiService` automatically intercepts the error and runs a **Local Matchmaking Algorithm**, pairing fighters in the same division with the closest ELO scores.

### Fantasy League System
1. Admins create upcoming `Events` and schedule `FightResults` (Pending state).
2. Fans use the frontend dashboard to submit `Predictions`.
3. Once the Admin finalizes the result, the system iterates through all associated predictions and awards points to users who guessed correctly, updating the global Fan Leaderboard.

## 6. Project Directory Structure

- `/src/Controller` - Contains all routing and business logic (e.g., `ResultController`, `AIController`).
- `/src/Entity` - Contains the Doctrine Models matching the database schema.
- `/src/Service` - Contains standalone business logic (e.g., `AiService` for API calls, `RankingService` for ELO math).
- `/templates` - Contains the Twig views. `base.html.twig` acts as the master layout.
- `/public/uploads` - The secure storage directory for images and video highlights.
- `/.env` - The environment configuration file storing database credentials and API keys.
